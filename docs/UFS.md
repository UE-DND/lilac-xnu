# Sony 只读 UFS 驱动

## 控制器交接

实测 UFSHCI 2.1 控制器的寄存器范围为 `0x01da4000..0x01da64ff`，中断为 INTID 297。LUN0 使用 4 KiB 块，当前设备的末尾 LBA 为 `0x00772bff`，GPT 包含 66 个分区。这些值应以目标设备的实际检查为准。

Fastboot 和 Sony ABL 可能留下不同的队列状态。驱动每次发现传输和任务管理队列，验证已完成命令、描述符及队列稳定性，不读取旧数据指针，也不重放旧命令。UIC 错误寄存器具有读清除行为，因此不放入常规观察路径。

## 传输与设备

`shared/ufs-read.c` 是 BootShim 和 XNU 共用的权威实现；固定编译路径使用相对符号链接。它只提交 LUN0 的 READ CAPACITY(10) 与单块 READ(10)，提交前检查操作码、方向、长度和描述符。传输借用固件留下的停止任务管理页作为 DMA 缓冲，保存并恢复相关页面。

初始化检查容量、MBR、主备 GPT 头和完整条目数组、分区范围及重叠，并读取分区边界。检查上限为 128 个分区、128 KiB GPT 条目和 512 条命令。超时后驱动保留可能仍被 DMA 使用的内存，停止后续读取，不复位控制器。

启用 `lilac_ufs=1` 后，XNU 完成初始化批次才发布 `/dev/lilac0`、`/dev/rlilac0` 和对应分区设备。块和字符设备均拒绝写入；传输或恢复异常会永久停用当前驱动。互斥锁串行化传输，用户复制在锁外进行。

`kern.lilac_ufs_info` 提供分区名称、LBA 和首尾 CRC；`kern.lilac_ufs_status` 提供状态和计数。`RAM restored=0` 也可能表示尚未进入修改流程，需要结合阶段和错误码判断。

## 检查

```sh
./lilac test host
```
