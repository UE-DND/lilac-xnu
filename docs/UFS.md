# Sony 只读 UFS 驱动

## 控制器规格与硬件初始化

高通 MSM8998 平台内置的 UFSHCI 2.1 控制器寄存器物理基地址范围为 `0x01da4000..0x01da64ff`，中断号配置为 INTID 297。存储设备 LUN0 采用标准的 4 KiB 物理块大小，分区表采用包含 66 个标准条目的 GPT 布局。

在系统引导交接时，Fastboot 与 Sony ABL 可能在控制器中遗留不同的硬件队列状态。驱动在初始化阶段动态发现传输队列与任务管理队列，严格校验已完成的命令、描述符有效性及队列寄存器的稳定性，不引用固件残留的过期指针，也不重放旧命令。UIC 错误寄存器由于具备读清除特性，不纳入常规轮询路径以避免状态丢失。

## 传输架构与只读设备发布

存储驱动的核心实现位于 `shared/ufs-read.c`，由 BootShim 引导器与 XNU 内核共用：

- **命令集限制**：驱动严格受限于只读操作，仅向 LUN0 提交 `READ CAPACITY(10)` 与单块 `READ(10)` 命令。在每次提交前，均全面检查命令操作码、传输方向、缓冲长度与描述符对齐。
- **DMA 缓冲借用**：传输流程借用原厂固件已处于停止状态的任务管理页作为 DMA 缓冲页面，并在使用前后完成页面内容的校验与状态恢复。
- **安全边界检查**：初始化阶段依次校验存储容量、MBR 分区、主备 GPT 头及完整分区条目数组，确认各分区物理范围无非法重叠。驱动设置了最多 128 个分区、128 KiB 分区条目及 512 条命令的上限保护。

在内核中启用 `lilac_ufs=1` 参数后，XNU 在完成存储自检与分区解析后发布 `/dev/lilac0` 块设备与 `/dev/rlilac0` 字符设备。这两类设备接口均显式拒绝所有写请求。传输层采用内核互斥锁对 I/O 请求进行串行化调度，用户态数据复制在锁外完成以优化吞吐性能。

## 状态监控与超时保护

驱动通过 `sysctl` 节点向用户空间提供运行时状态：
- `kern.lilac_ufs_info`：提供各分区的名称、起止 LBA 扇区号及首尾校验码。
- `kern.lilac_ufs_status`：提供当前累积读取成功的 4 KiB 块数（`blocks`）、请求批次数（`batches`）以及在传输层消耗的计时周期（`read_ticks`）。

### 传输超时处理机制

命令轮询机制在超时期限到达后，会再次复核硬件门铃寄存器状态。若此时检测到命令完成，则继续校验 OCS 状态码与响应 UPIU；若控制器状态仍处于繁忙，驱动将永久停用并保留可能正在被硬件 DMA 访问的内存页面，拒绝后续所有存储请求，从而防止内存数据被意外篡改。

## 自动化测试

```sh
./lilac test host
```

主机单元测试套件基于模拟控制器与虚拟磁盘，全面覆盖只读命令校验、GPT 边界防护、超时回退及错误停用等逻辑。系统卷的虚拟化映射机制请参阅 [UFS 系统镜像映射](UFS-SYSTEM.md)。
